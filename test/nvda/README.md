# 真 NVDA 對照（手動驗證工具）

我們的「NVDA 報讀預覽／朗讀順序」是一套**模擬**——用詞逐字校對自 NVDA 官方
`zh_TW.po`，但「何時念什麼、順序怎麼組」是我們自己的模型。這個工具用 **Guidepup
驅動真正的 NVDA**，擷取它實際念出的每一句，與我們的 `__rampA11yReadingOrder`
輸出並排比對，用來校準模擬的忠實度。

## 安裝與執行

```sh
npm install
npx @guidepup/setup                 # 裝 Guidepup 專用 NVDA（含 NVDA Remote 附加元件）
npm run test:nvda                   # 對照 test/nvda-fixture.html
npm run test:nvda -- reading-order-fixture.html   # 換頁面
```

## ⚠ 焦點注意（為何維持手動、不進 CI）

NVDA 跟隨**鍵盤焦點**朗讀。Windows 的前景鎖定不允許背景腳本可靠地把焦點搶到自動
開啟的瀏覽器——因此工具會開一個瀏覽器視窗，並**請你在倒數內親手點一下該視窗**，
NVDA 才會讀到該頁。若焦點仍在別的視窗（例如開著的「設定」視窗），請先關掉它們。
這是需要互動桌面的操作，因此不放進 `npm test` 的自動化迴歸。

## 目前已知的對照結果

即使自動化焦點卡在別的視窗，真 NVDA 在真實控制項上念出的**格式與我們的模擬一致**，
已可佐證核心用詞與組合正確：

| 面向 | 真 NVDA 實際念出 | 我們的模擬 |
|------|-----------------|-----------|
| 集合位置 | `8 之 2`、`12 之 2`、`3 之 2` | `{總數} 之 {序位}` ✅ |
| 標題階層 | `第 1 級`、`第 2 級` | `第 N 級`／`標題第 N 級` ✅ |
| 選取狀態 | `沒選取` | `沒選取`／`已選取` ✅ |
| 群組角色 | `群組` | `群組` ✅ |

待「NVDA 讀到本頁」的完整逐句對照補上後，可據以微調模擬的斷句與組合順序。
